Generate the storage-layout header for an in-memory, read-only analytical C++ query engine.

You are given one hint level: the schema facts, and — depending on the level — the storage-plan hints that accompany them. Implement exactly what the level text supports and nothing more.

The header must contain:

1. The column and table structures
   - One struct per table, holding its columns as contiguous containers.
   - Variable-length values as an offset array plus a character data array, not as a container of std::string per row, unless the level text says otherwise.
   - Nullability only for columns the schema marks nullable.
   - Fixed-width encodings where the level text calls for them (dictionary ids for low-cardinality strings, integral days for dates, narrowed integers).

2. The database structure
   - One struct aggregating every table, plus whatever lookup structures the level text describes.
   - A declared entry point for ingestion; its definition belongs in the loader, not here.

3. Access-path members the level text justifies, and no others.

Hard rules:
- Everything goes in one self-contained header, wrapped in `#pragma once` and the namespace you are given.
- Header-only: declarations, type definitions and inline functions. No I/O, no Parquet reading, no query logic.
- Include only what you use, from the standard library.
- Compile cleanly under the project's C++ standard. Prefer std::vector and fixed-width integer types from <cstdint>.
- Do not invent tables, columns, indexes or encodings the level text does not support. If the level text omits something you would need, leave it out rather than guessing.
- Name types and members after the schema's own names so later stages can find them.

Output only the header source. No prose, no markdown fences.
